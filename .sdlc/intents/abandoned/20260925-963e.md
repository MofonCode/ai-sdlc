# Charter protection becomes a mechanism instead of a sentence

> **ABANDONED, not rejected.** This intent was correct and was withdrawn for a process
> reason: it was filed as the first cycle while the concept was still incomplete, which
> is exactly what we had agreed not to do. Everything below stands as a design record —
> the two decisions in it, fail-closed in every case and four protected paths, were made
> deliberately and are what the hook should be built to.

## What is wrong

**INV-08 is the only invariant in this charter enforced by asking nicely.**

Every other rule is enforced by being *citable*: a finding points at it, the finding earns a
citation, and the cycle halts. INV-08 forbids "amending this document, the stack pack, or the
pack rules outside an approved charter or pack intent" — and nothing checks it. The rule is
repeated in three skills as prose, and prose is what an agent is asked to follow rather than
what it is prevented from breaking.

That is backwards for the reason the charter itself gives: this is the rule with the most to
lose. Without it, a cycle that edits its way around an invariant leaves no finding behind.

It is also a claim I made and had to retract. I said the gate boundary was runtime-enforced
and it is not: what actually enforces the gates is the artifact model plus the landing script.
This intent closes the hole rather than restating it.

## How we will know it worked

Observable, not a feeling:

- An `Edit` or `Write` to `.sdlc/CHARTER.md` from a session that is **not** on a
  `charter-review` branch is **refused**, and the refusal says why.
- The same edit from a session that **is** on one succeeds.
- A test asserts the refusal, not the permission. A protection test that only proves the happy
  path proves nothing.

## What should happen when it fails

**Fail closed, in every case.** Decided deliberately, because a protection that opens when it
is confused is the INV-06 erosion failure wearing a different hat — it stops working and
nothing announces that it has.

| Situation | Behaviour |
|---|---|
| on `intent-<id>` or `cycle-<id>`, and that intent's `source` is `charter-review` or `pack-review` | **allow** |
| on `master`, or any branch with no cycle | **deny** |
| detached HEAD, or the branch cannot be determined | **deny** |
| the intent file for the branch is missing or unreadable | **deny** |
| the hook script itself errors, or its input will not parse | **deny** |

**The consequence, stated plainly rather than discovered later:** after this lands, a charter
edit through Claude Code is impossible except on a `charter-review` branch. That includes my
own edits, and it includes the already-planned removal of DEC-08 — which will have to be done
on an intent branch, exactly as the charter says.

**The escape hatch is a person, and that is the design.** A hook can be disabled, and doing so
is loud and deliberate. INV-08 says a cycle "can request; only a person can grant" — a hook
that a person can switch off and a process cannot is precisely that sentence made mechanical.

**What this does not protect against, and must not claim to.** A hook only sees Claude Code
tool calls. A person editing the charter in an editor, or running `git` directly, is untouched.
That is not a gap to close: it constrains the automated process, which is what INV-08 is about.

## What is protected

- `.sdlc/CHARTER.md`
- `packs/*/pack.yaml`
- `packs/*/pack.rules.yaml`
- `packs/*/CHARTER.md`

The last one is a judgment worth recording. INV-08's wording is "this document, the stack pack,
or the pack rules", and a pack's charter template governs nothing until a solution copies it —
so a narrow reading would leave it out. It is in scope because it is the most consequential
file in a pack: every solution created from that pack inherits it, and an ungated edit to it
changes the rules every future solution is judged by.

## What is explicitly out of scope

- **Any other invariant.** This is about INV-08 only. Making the rest mechanical is a different
  question and a much larger one.
- **Deleting or weakening the prose.** The skills keep saying "do not touch the charter". A
  refused tool call explains itself at the moment of refusal; the prose explains it while
  someone is deciding what to do. Both are wanted.
- **`.sdlc/intents/`, `.sdlc/cycles/` and the schemas.** They are governed artifacts but INV-08
  does not cover them, and widening scope past the invariant would be the thing this framework
  calls scope drift.
- **Enforcement outside Claude Code.** See above: not a gap.

## A deployment fact this cycle does not resolve

The hook ships as a plugin component, so it takes effect when the installed plugin is next
updated — not when this cycle lands. The plugin is installed from the marketplace at
`#bootstrap`, so until `release` exists and is pointed at, the hook will be present in the
repository and inert on this machine.

That is not a defect of this work, and it is not this cycle's job to fix. It is recorded so
nobody concludes the hook is broken when it is merely not yet installed.
