# Seven blocking findings from the charter's second interrogation — one of them changes when INV-08 commences

The charter says several things about itself and about this tree that are no longer true, and
two of its passages contradict each other. An interrogation of `.sdlc/CHARTER.md` at version 3
found **seven blocking findings**, every one of them cited: three point at two conflicting
locations in the document, four cite the invariant forbidding an artifact to assert a fact about
the repository that no check verified.

**This intent proposes to amend the document on all seven.** It does not propose the wording —
each amendment is an edit to be reviewed on the branch, and the finding's own suggested repair is
a suggestion rather than a decision.

**It says so in its title because one of the seven changes INV-08.** The commencement passage is
what decides when the charter-protection rule binds, so narrowing it narrows INV-08's own reach.
The self-reference cannot be closed — the rule lives in the document it protects — so the only
failure mode that matters is quiet removal, and this is the loudness that answers it.

## What is wrong

The findings are filed at `.sdlc/cycles/20260926-bc24/findings/charter.r1.json`. In the order the
interrogation produced them:

**1 · The register calls a finding noise and the disposition table calls it evidence.**
`charter-r1-reason3`, two locations. The open-decision register says an interrogator that raises a
finding about a deferred decision "is producing noise". The disposition table says such a finding
is real, is dismissed as `deferred-to-dec`, and that its accumulating cite count is the signal the
subject is ready to be decided. Both cannot hold: repeatedly producing noise cannot also be the
strongest available evidence. The register's prohibition — nothing in it may halt a cycle — is
correct and is not what is in question.

**2 · The charter requires the retro copy and denies it the exemption.**
`charter-r1-reason4`, two locations. Dispositions must be recorded in `verify.md` *and* carried in
`retro.md`, because the retro is what travels and the amendment signals are computed from it. Yet
INV-03's Scope clause still says "None is built yet, so the retro corpus does not currently
qualify". As written the charter mandates a copy it also forbids.

`tools/Import-SdlcRetro.ps1` now makes that copy and refuses to overwrite an entry whose content
differs, which is the exact condition the exemption names. **The pack charter shows the shape to
aim for:** it states the condition — *provided the mechanism making the copy refuses to overwrite
with differing content* — and asserts nothing about what is currently built. A rule that carries a
status report needs an owner to keep it true; a rule that states its condition evaluates itself.
So the proposal is to delete the status claim rather than update it.

Deliberate divergence from the finding's suggested repair: it proposes adding
`Prevented-by: tools/Import-SdlcRetro.ps1`. That field means "a template or check guarantees
compliance with this invariant", and the import script guarantees one instance of INV-03 out of
every artifact and every line of code it governs. Naming it would make the zero-cite query read
the whole invariant as prevented upstream, which is weaker than leaving the question open.

**3 · Coverage keeps a derived column the document's own rule says to delete.**
`charter-r1-reason6`, two locations. Version 2 deleted the `Applies-to:` summary matrix precisely
because it restated derived data with nothing binding it, and recorded the rule: the fix for
derived data in a hand-maintained document is to delete it rather than promise to keep it in step.
The Coverage table's second column restates which invariant unlocks each category, derived from
the invariants' own `Unlocks:` clauses, with nothing binding the two. Its first column *is* bound,
by `TaxonomyBindingTests`. So this is the same defect that was fixed once, surviving in the next
column along, and the two permitted answers are the ones the document already names: delete the
column, or bind it in the same change.

**4 · The signals table claims one source and has two.**
`charter-r1-reason13`, citing INV-07. The section says every signal is derived from the findings
corpus by a read-only query. The "repeated rejected charter intents" row is not in the corpus at
all: a refused request leaves no finding behind, so that count is read from the abandoned intent
files by `tools/Find-SdlcCharterIntent.ps1`, while `tools/Get-SdlcSignals.ps1` computes the
zero-cite, high-override and suggestion-cluster signals. The mechanism is built and tested; the
description of it is wrong. The load-bearing half — that no signal is ever stored — is true and
stays.

**5 · INV-06 claims a comparison nothing performs.**
`charter-r1-reason15`, citing INV-07. Its Evidence says the suppression count is tracked in every
`verify.md` and that an increase is itself a finding. `suppression-count` is optional in
`schemas/verify.schema.json`, and nothing compares a cycle's count against the previous one. This
needed cross-cycle state that did not exist; the retro now carries `suppression-count` and the
corpus is readable, so the choice is to build the comparison or to narrow the claim to what is
true. Either is an honest answer; asserting it while nothing does it is not.

**6 · Commencement is already overtaken by the gate.**
`charter-r1-reason16`, citing INV-07. The passage says that until the first cycle runs against the
charter the document is a draft with no process to protect it from. `hooks/hooks.json` installs an
unconditional `PreToolUse` deny on `.sdlc/CHARTER.md`, carrying no commencement condition — and no
cycle has yet run in this tree. The protection commenced when the hook shipped, not when the rule
said it would. **This is the amendment that touches INV-08**, because commencement is what decides
when INV-08 binds.

**7 · The roles passage overstates what the interrogator keeps.**
`charter-r1-reason19`, citing INV-07. It says the interrogator reads the roles from this document
through fact-gathering "rather than carrying its own copy". `workflows/interrogate.js` keeps the
role *names* in three places: the candidate schema's `role` enum and both `wanted` arrays that
perform the `form`-for-`charter` substitution. Version 3 removed the role *definitions* — the
question, the evidence, the characteristic failure — and that change stands. What remains is a
copy of which roles exist, and it is bound by tests rather than derived, which INV-03 permits
explicitly. The wording is what is wrong.

## How we will know it worked

- Re-interrogating `.sdlc/CHARTER.md` after the amendment produces **none of these seven**.
  That is the observable test, and it is the same instrument that found them.
- The charter's frontmatter carries `version: 4` and an `amended:` line naming this intent. The
  version is the interpretation key for every retro, so an amendment that does not move it makes
  older retros silently mis-attributable. This has happened once already: a register change landed
  on 2026-09-24 and the version did not move.
- Each of the seven is either **fixed** in the amendment or dispositioned `rejected` or
  `accepted-wont-fix` with a reason. None is left outstanding, and a dismissal that is right about
  the finding being wrong must not be recorded as an override — the two feed opposite signals.

## What happens when it fails

- **A reviewer rejects some of the seven.** Expected, and the reason this intent itemises them: the
  pull request carries one edit per finding, so approving five and rejecting two is a normal
  outcome. The rejected ones are dispositioned `rejected` — the finding was wrong — or
  `accepted-wont-fix` with the reason, and the charter is amended to whatever survived.
- **The whole intent is refused.** Then it lands in `intents/abandoned/` with a `reason:`, the
  charter stays at version 3, and the reason is on master for the next cycle that trips over the
  same contradiction. Nothing is left half-changed, because the request and the edit are in one
  pull request that merges either way.
- **An amendment introduces a new contradiction.** The measured behaviour of repairs, not a
  hypothetical: a repair round is where findings are introduced. The re-interrogation above is what
  catches it, and the no-progress rule is what stops the loop if wording changes stop converging.
- **The version is not bumped, or `amended:` is not recorded.** Nothing checks this today. Until
  something does, it is a review obligation on the pull request rather than a guarantee.
- **The hook refuses the charter edit.** Correct behaviour if the edit is attempted anywhere but
  this intent's branch. The gate reads the branch name, finds this intent, and requires
  `source: charter-review` — which is why the edit cannot precede the intent.

## What is out of scope

- **DEC-08 stays in the register.** The private-marketplace credential path is proven for one
  identity on one machine. The question includes whether it works for somebody else, and that is
  answered when a teammate installs — not before. Striking it now would record an answer we do not
  have.
- **The 21 suggested findings.** They do not halt anything and they accumulate as evidence; a
  recurring cluster on one theme is how a missing invariant is identified. They are triaged on their
  own schedule, and a promoted one becomes an ordinary intent with `source: suggestion`.
- **Building the suppression-count comparison (finding 5).** If the answer to that one is "build
  it" rather than "narrow the claim", the building is ordinary work in its own cycle. This intent
  changes the charter and nothing else.
- **Any code change.** Findings 5 and 7 name real gaps between the document and the tree, and both
  could be closed from either end. This intent proposes closing them from the document's end, and
  says so rather than leaving the choice implicit.
