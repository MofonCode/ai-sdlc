# Intent · Artifact model, layout, and findings schema

## 1 · Problem

Nothing in this repository defines where a cycle's artifacts live or what they carry.
Every later piece of work either produces or consumes those artifacts — fact-gathering
reads them, the interrogator emits findings into them, the repair loop reads findings
back, the retro carries them between repositories — so all of it is blocked on a format
that does not exist.

The design record names paths inconsistently (`intents/<id>.md`,
`suggestions/<cycle-id>.md`, `retros/<solution>/<id>.md`, `.sdlc/CHARTER.md`) without
ever fixing a root, and names artifact fields in passing without collecting them. The
findings schema is described but not written.

Nothing can be verified against an undefined format, so nothing after this is testable.

## 2 · Outcome

A findings schema that mechanically rejects malformed findings, a settled artifact
layout, and a test project that proves both against example artifacts.

After this, a later cycle can be built against a fixed target instead of a description.

## 3 · In scope

1. **The findings schema**, as a JSON schema file. It must make an uncited `blocking`
   finding unemittable, because that is the anti-inflation guard and a convention nothing
   enforces is not a guard.
2. **The artifact layout** — one root, and the position of intents, cycle artifacts,
   suggestions, retros and the charter within it.
3. **The field set per artifact**, collected in one place rather than scattered.
4. **A test project** (MSTest, `net10.0`), since nothing here can currently be verified
   at all.
5. **Example artifacts** for each kind, valid and invalid, that the tests validate
   against the schema.

## 4 · Out of scope

1. **Stage templates.** Each stage's template belongs with the cycle that builds that
   stage. This intent defines shapes; it does not fill them in.
2. **Any skill or workflow.** No stage is implemented here.
3. **The plugin manifest and marketplace wiring.** That is packaging, and it is later.
4. **Aggregation over the retro corpus.** The corpus is empty and will stay near-empty
   for weeks; building a reader for it now would be guessing at what the data looks like.

## 5 · Decisions this intent must settle

These are genuinely open. The design record does not answer them.

1. **Do cycle artifacts group by cycle or by kind** —
   `.sdlc/cycles/<id>/spec.md` against `.sdlc/specs/<id>.md`? Intents deliberately group
   by kind because they exist before any cycle and form the queue; whether cycle
   artifacts follow that or group per cycle is undecided, and the asymmetry needs stating
   either way.
2. **The `source` enum.** `maintain`, `suggestion`, `charter-review` and `pack-review`
   are named in the design record. No value exists for an ordinary human-authored intent,
   and this file uses `seed`, which is a placeholder.
3. **Whether the layout is enforced by an invariant** or is merely a convention the
   skills follow. If a solution can put artifacts anywhere, fact-gathering cannot find
   them; if it is an invariant, it is citable.
4. **How a location pair is expressed** in a finding. The charter permits it as a
   citation for `internal-contradiction`, without saying what it looks like — file plus
   line, file plus section heading, or something else.

## 6 · Constraints

1. Where this intent and the charter disagree, the charter wins.
2. The findings schema is the authority for its own values; this intent must not restate
   the category, state or disposition enums, which the charter already owns.
3. The schema must be machine-validatable by the test project without a network call.
4. This intent's own file is written in a format it is meant to define. That circularity
   is expected: the format is fixed by building, and this file will be the least
   conformant artifact in the repository when the cycle lands.

## 7 · Failure modes

The ways this can be complete and still wrong:

1. **A schema nothing validates against.** The file exists, no test exercises it, and the
   first malformed finding is discovered by a human reading output. Mitigated by scope
   item 5 — invalid examples are as necessary as valid ones.
2. **A schema that accepts an uncited `blocking` finding.** The guard is stated in the
   charter and unenforced in practice, so state inflation returns and the repair loop
   stops converging. This is the single highest-value thing the schema does.
3. **A layout that fact-gathering cannot enumerate cheaply.** If finding a cycle's
   artifacts requires reading files to discover their kind rather than looking at paths,
   the pre-check becomes expensive and the measured saving that justified it is lost.
4. **Fields settled for the artifacts this cycle touches and guessed for the rest.**
   `verify.md` and `retro.md` are the most complex and the furthest away, so they are the
   likeliest to be specified wrongly here and corrected later — which is acceptable only
   if their ids and enums are right, since those cannot be renumbered.
5. **A test project that only proves the schema is well-formed JSON.** Schema validity is
   not the same as the schema rejecting what it should reject.
6. **Silence about the asymmetry in decision 1.** If cycle artifacts group differently
   from intents and nothing records why, the next person reads it as an inconsistency and
   changes one of them.

## 9 · Notes

This is the first artifact intended to move through the framework's own process, and it
is the test of whether the charter functions as an authority. Three things it should
reveal, and at least one is expected to come back badly: whether `interrogate` can cite
anything against an intent; whether the `Forbids:` clauses survive contact with a real
artifact; and whether the intent shape above is the right one.
